# W39 coverage audit — local-mbp14

Audit date: 2026-09-24. Machine: local-mbp14 (the machine that ran the retro). All reads were read-only: sqlite through `?mode=ro` / `?immutable=1`, jsonl through line-by-line parse. No app UI was driven.

**Audit window (strict):** `2026-09-17T12:00Z ≤ event timestamp < 2026-09-24T12:00Z`, applied to each event.
**Collector window (W39.json):** file mtime or session start `≥ run_ts − 7d`, where run_ts = `2026-09-24T12:16:03Z`. The collector window therefore also includes activity from 12:00–12:16Z on 09-24, and every line of a file that was modified in the window.

Every mismatch below has a tag: **[window-def]** means the difference comes only from the two window definitions and is not a bug. **[collector-bug]** means the collector counts the wrong thing or misses a store.

Scripts: session scratchpad (`codex_audit.py`, `claude_audit.py`, `agy_final.py`, `cursor_audit.py`, plus inline one-offs). They are not committed.

## Findings

1. **codex under-count is real, and the with-archive number is right.** 22 sessions (cmli) is the correct count for sessions that started in the window. 23 is the count including 1 resumed session. The real token figure is 37.66M (strict) / 37.78M (W39 `with_archived`, which includes 122,531 pre-window tokens). The `codex.total` = 210,468 is one human ping's lifetime cumulative, not W39 work.
2. **All non-Claude CLI traffic this week is tmux-agent-tools workers.** This holds for codex (18/18 archived), agy (all dbs with steps), and cursor (25/25 transcript user turns). Humans only pinged each tool once near 11:30–12:10Z ("hi" in Codex Desktop, "Hello There" in cursor, `/remote-control on` in agy), and 2 of those 3 fall after the window end.
3. **~/.gemini activity is agy only.** gemini-cli has no activity. There is no double count between them.
4. **cursor "2 unreadable" is a false alarm.** It is 2 empty chat dirs (`hasConversation:false`, no store.db). The W39 gap claim "messages 低估" is wrong.
5. **"無記帳" is wrong for 2 stores.** agy `gen_metadata` has a per-generation usage sub-message (semantics UNCONFIRMED). grok CLI `usage.json` records tokens and cost (0 this week).
6. **grok "store absent" is a false-absent on this machine.** The collector reads only the VM seat layout.

## Collector changes needed

- `codex-tokens.py`: also read `~/.codex/archived_sessions/*.jsonl`, and dedupe by `session_meta.payload.session_id`.
- `codex-tokens.py`: sum the in-window delta of `event_msg.token_count.info.total_token_usage` (last in window − last before window), not the last cumulative per file.
- cmli `collectCodex`: select a session by any event `timestamp` in the window, not only by `session_meta.payload.timestamp` (misses resumed sessions such as the 08-27 Codex Desktop thread).
- cmli `collectAgy`: window each step by `steps.metadata` protobuf field `/1/1` (unix seconds), not by db mtime. Report 0-step dbs separately.
- cmli `collectAgy`: add `COUNT(*) FROM gen_metadata` (generations) and, after the schema is confirmed, the `/1/4` usage sub-message sums. Stop reporting "無記帳".
- cmli `collectCursor`: use `max(meta.updatedAtMs, store.db mtime)` as the stamp (the two stamps disagree by more than 1h in 10/22 chats).
- cmli `collectCursor`: report `meta.json`-only dirs with `hasConversation:false` as `empty`, not `unreadable`.
- cmli `collectCursor`: optionally add `~/.cursor/projects/*/agent-transcripts/*/*.jsonl` user lines as the turn count (store.db has no per-message timestamp).
- cmli `collectGrok`: on a workstation, read `~/.grok/sessions/<urlenc-cwd>/<sid>/usage.json` (tokens, modelCalls, turnCount, costUsdTicks) and `events.jsonl` timestamps. Report "absent" only when both layouts are missing.
- Grok Bot app: no token collector (the VM is authoritative). At most, add a device-attribution count from the `sand-client-persistence` `transcript.replicas.*` entries (`timestampMs`), labelled as a lower bound and never added to fleet totals.
- `usage-dedupe.py` / analyzer: filter by line `timestamp` in `[start, end)`, not by file mtime (+40.25M pre-window tokens this week).
- All collectors: take explicit `--since/--until` ISO timestamps (the retro window is 12:00Z), not `now − 7d` at run time (12:16Z).
- Claude `turns`: exclude user text that starts with "The tmux-agent plugin sent a message" (526 in window) from `human_messages`.
- gemini-cli, opencode, aider: add a zero sentinel (store path + newest activity timestamp), so that a 0 is reported with evidence rather than as a missing key.
